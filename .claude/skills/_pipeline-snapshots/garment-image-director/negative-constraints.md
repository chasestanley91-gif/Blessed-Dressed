# Negative constraint system

Every prompt carries two negative blocks, kept deliberately separate:

## 1. Universal negatives (`NEGATIVE` in `lib/prompt.mjs`)

Apply to **every** option, regardless of what it is: no illustration/line-art
style, no CGI/3D-render look, no cartoon, mannequin, or fashion sketch, no
inaccurate geometry or altered proportions, no missing construction, no
asymmetry, no watermark, no AI-art appearance — and, specifically, no
reproduction of the tech pack's own annotations (measurement numbers, units,
dimension/leader lines, arrows, guide marks, ruler ticks, labels). These are
manufacturing documentation on the drawing, not features of the cloth, and
must never appear in the photograph.

## 2. Per-option forbidden list (`spec.forbidden`, from tech-pack-interpreter)

This is what makes the system match the user-facing rule "negative
constraints must be generated from the specific option, not one generic
negative prompt for every garment." `computeForbidden()` in
tech-pack-interpreter's `lib/spec.mjs` derives this per spec, before any
photography concern exists:

- **Absence guard** — if the option is the deliberate absence of a feature,
  the exact feature name is forbidden ("any back vent rendered anywhere in
  frame — this option is its deliberate absence").
- **Generic-category substitution** — always present: forbids a generic
  version of the part standing in for the exact drawn option.
- **Option isolation** — always present: forbids borrowing a feature, count,
  or geometry from a neighboring craft option on the same field.
- **Front/back lock** — always present: forbids a feature that belongs on
  the opposite face of the garment from what the illustration shows.
- **Exact counts** — for every parsed count token (`'2-button'`, `'6-loop'`,
  `'1-hook'`), forbids any count other than that exact number.
- Structural specifics like "no back vent" or "no side adjuster" when the
  spec's shapes/flags say so.

This block is rendered in the prompt as `FORBIDDEN FOR THIS OPTION — do not
render: <list>.` (see `buildPrompt()` in `lib/prompt.mjs`), always after the
universal `NEGATIVE` block.

## Why two blocks instead of one

Folding everything into one static negative prompt is exactly the failure
mode the user's original spec calls out — it either has to be so generic it
misses option-specific risks, or it has to be hand-written per option (which
doesn't scale to a catalog with thousands of options). Splitting it lets the
universal block stay genuinely universal (photography-style negatives that
never change) while the per-option block is mechanically regenerated by
`computeForbidden()` every time the spec changes — no drift, no manual
authoring per option.

## Extending it

New universal failure modes (a new AI-art tell, a new stylisation risk) go in
`NEGATIVE`. New *structural* forbidden patterns (a new kind of
front/back-confusable feature, a new count family) go in
`computeForbidden()` in tech-pack-interpreter — this skill should never grow
its own parallel structural-negative logic; that would reopen the exact
drift risk the split was meant to close.
