### Structural defect found and fixed: "failure-aware" retries were not failure-aware

The owner's rejection reasons were stored **only** as text appended to `prompt.json` after
the fact (`apply_owner_approvals.mjs` → `OWNER CORRECTION AFTER REVIEW` + a structured
`ownerCorrections[]`). `build_prompt.mjs` knew nothing about them. Two consequences:

1. Any `build_prompt.mjs --write` rebuild silently erased the block. The only guard was a
   prose warning to humans in `generation_wave.workflow.js:49`.
2. Worse, `tools/prep_batch.mjs` generates from a **freshly built** prompt
   (`build_prompt.mjs --json`, never `--write`), which therefore **never contained the
   correction at all**. A state-C retry driven through prep_batch would have regenerated
   with no knowledge of why the owner rejected it — a direct V4 §7 violation, and a likely
   cause of repeat rejections for the same reason.

**Fix:** `build_prompt.mjs` now carries `ownerCorrections[]` forward and re-emits the block
as a DERIVED part of every build, appended last so it still outranks earlier lines. No
rebuild can drop it, and every consumer (including prep_batch's in-memory build) gets it.

Verified on `shirt/bias-outer-top-collar` (1 existing correction):

- fresh `--json` build → `ownerCorrections: 1`, exactly 1 block in the prompt text
- two consecutive `--write` rebuilds → still 1 and 1 (idempotent, no duplication)
- `validate_prompt.mjs` → `1/1 option(s) passed the pre-flight gate`, exit 0
- test file restored to its committed bytes afterwards

### Pre-generation note: prompts are rebuilt per wave (staleness is handled)

**297 of 299 `prompt.json` files predate the current template logic** (`lib/prompt.mjs`,
2026-08-08); 110 date to July. Rebuilding one (shirt/collar-regular-20) produced a
materially different prompt (117 insertions / 133 deletions).

This is **not** a blocker: `tools/prep_batch.mjs` re-runs `extract_spec.mjs --write` and
then builds the prompt fresh for every craft it prepares, so a wave never generates from a
stale on-disk prompt. Combined with the correction-carry-forward fix above, a fresh build
now includes the owner's rejection reasons too — which is what made the rebuild safe to
rely on in the first place.
